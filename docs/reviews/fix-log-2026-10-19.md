## 2. HIGH-01 — Quarantine rules ran only in `analyze`; `parse` and the builders accepted anything

**Status:** fixed
**Files:** `engine/parse/worker.py` (`quarantine_reason`, `parse_one`, `run`),
`engine/cli.py` (`cmd_parse`, new `_quarantine_results`, `_build_one`),
`test/engine/test_parse_worker.py`, `test/engine/test_audit_items.py::high_01`,
`docs/ENGINE_CLI.md`, `docs/ENGINE_ENV.md`

**What changed**
- `worker.parse_one` now reads the header (with roster) and runs
  `awpy3_parser.quarantine_check` before every parse. A failing demo returns
  `status: quarantined` with the `reason` (or `header_unreadable`) and its path; nothing
  is parsed or written and it is not counted as `failed`. `run()` passes the injectable
  `header_fn` to the parse jobs too (fakes in tests, pickled for the pool).
- `cli parse` (not `--smoke`) follows through: a quarantined result whose match has a
  `matches` row is moved under `demos/quarantine/<reason>/` with

  result says `moved: true/false`. Move failures are logged, never raised.
- `cli._build_one` refuses a match whose row is `quarantined` (before reading parsed
  tables) so `build-states --all` / `build-actions --all` can no longer overwrite the

  read, not in `register_demo`.

**Verification**

  and unreadable demos are quarantined with nothing written; the pool applies the gate;

## 3. MED-01 — Two divergent quarantine rule sets

**Status:** fixed (with HIGH-01, same commit)
**Files:** `engine/data/quarantine.py`, `test/engine/test_quarantine.py`

**What changed**
- `engine.data.quarantine.check` no longer carries its own thresholds, map pool and
  reason names (`tick_rate`, `few_rounds`, `duration`, keys `players_ct`/`players_t`
  that no producer emits). It delegates to `awpy3_parser.quarantine_check` after
  filling every required key (`REQUIRED_KEYS`) with None, so a missing key is judged
  as unverifiable instead of skipped. `REASONS` is the parser's vocabulary plus
  `header_unreadable`; `KNOWN_MAPS` is `engine.maps.assets.ACTIVE_POOL` (one list;
  `engine/sources/hltv.py` keeps importing the name).
- `quarantine()` therefore accepts exactly the reasons the worker and `analyze` emit;
  the legacy names raise `ValueError`.

**Verification**
- `test_quarantine.py` rewritten to the shared vocabulary: 35/35, including "one reason
  vocabulary with the parser", "one map pool with the assets module", "same verdicts as
  the parser on a full meta", and a per-key "missing key is judged" sweep.
- Covered by the HIGH-01 `run_all` above.
