## 1. CRIT-01 — `.gitignore` `data/` also ignored the source package `engine/data/`

**Status:** fixed
**Files:** `.gitignore:25-27`, `engine/data/` (7 files, now tracked),
`test/engine/test_audit_items.py` (new)

**What changed**
- The unanchored rule `data/` matched every directory named `data` anywhere in the
  tree, so `engine/data/` (dataset, splits, quarantine, inventory, layout, qa) was
  never committed and the pushed repo could not run build-states, build-dataset,
  train-wp, calibrate, eval, inventory or 18 test scripts from a fresh clone.
- Rule changed to the root-anchored `/data/` with a two-line comment naming the
  reason. `data/engine/engine.db` and `data/_tmp_demos/` are still ignored
  (`git check-ignore -v` confirms rule `.gitignore:27:/data/` for both);
  `engine/data/*.py` is no longer ignored and is committed in this change.
- New test script `test/engine/test_audit_items.py` with `crit_01()`: runs
  `git check-ignore --no-index` over every `*.py` under `engine/`, `test/` and
  `bench/` (204 files) and fails if any is matched by an ignore rule; also asserts the
  seven `engine/data` modules are present. Skips (exit 2) only if git is unavailable.
  The script holds one function per audit finding from here on; review-loop items
  (P11.2.3) stay in `test_review_items.py`.

**Verification**
- `test_audit_items.py` against the old rule (gitignore stashed): 1/2 passed, the
  ignore check fails as intended. Against the new rule: 2/2 passed.
- `python -m pyflakes engine test bench`: clean.
- `test\run_all.py`: see the run recorded below the entry.

**Open:** none. The definitive check is a fresh clone of the commit plus
`test\run_all.py`; its result is appended to this entry once the commit exists.

**Also in this change:** the secrets block of `.gitignore` gains `/env` (a dotless
`env` file at the repo root is a one-keystroke typo for `.env`, and the existing
`.env*` pattern does not match it).
